# P3 (remaining) — Hub Seam Implementation Plan

> Node-side chat relay + full sysinfo + the real-process e2e test already landed (commit
> b3733c6). This plan covers the HUB side. Per-task: tests → `scripts/coverage.sh` ≥90% →
> **codex review to convergence** → commit. Integration tests go in `tests/`.

**Goal:** the hub's `/v1/chat` (and `/api/higgs/*`) transparently use **remote** workers on
paired nodes — resolve `model → (node, worker)`, send over a per-node iroh transport, and
relay the stream back — alongside the hub's own local worker.

**Architecture (codex-validated 2026-06-19 — supersedes the spec's `remote_factory`/`WorkerProc`):**
The hub does **not** wrap remote workers in a `Supervisor`. It keeps its local `Supervisor`
for its OWN llama.cpp child only, and adds a lightweight **per-node transport client**:

```
/v1/chat → route model→(node_id, worker_id) → NodeTransport(node_id).chat(worker_id,…)
         → iroh M_CHAT → node Supervisor::chat() → N_CHAT_CHUNK + final back → SSE
```

`WorkerProc` and `remote_factory` are **dropped** (no remote-as-process masquerade). Remote
unload/kill are explicit `higgs/node/*` control RPCs; remote death = connection close → retire.

## Components

| File | Responsibility |
|---|---|
| `src/node/transport.rs` (NEW) | `NodeTransport`: owns the live `Connection` to one node + its OWN `actor::ReplyDemux` (NOT the hub's local Supervisor demux). `request(method, params)` (control) and `chat(worker_id, …) -> (chunks, fut)` mirroring `Supervisor`'s shape but over iroh. One bidi stream per call; a per-stream reader correlates responses (by JSON-RPC `id`) and `N_CHAT_CHUNK` (by `request_id`). Hub uses the SAME value for `id` and `request_id` (codex). |
| `src/node/fleet.rs` (NEW) | `HubFleet`: `HashMap<NodeId, NodeTransport>` (paired/connected nodes) + `model → (NodeId, WorkerId)` routing built from inventory. Node disconnect → fail pending + clear sinks + retire (HG027). |
| `src/api.rs` / `src/serve/v1.rs` | Route a `/v1/chat` to the fleet when the model is remote-resident, else local `Supervisor`. Keep the two correlation domains separate (§2.3). |
| `src/diagnostic.rs` | `HG027 NodeUnreachable` (+ `HG025`/`HG026` when P4b/#18 land). |
| `tests/remote_hub_e2e.rs` (NEW) | Spawn a real `higgs --node`; the test drives the **hub library** (`HubFleet`/`NodeTransport`) — pair, route, `/v1`-style chat to the remote worker, assert streamed tokens; SIGTERM teardown for coverage. |

## Tasks (each: TDD → gate ≥90% → codex converge → commit)

1. **`NodeTransport`** — connection + `ReplyDemux` + per-stream reader; `request` + `chat`.
   Unit-test against the node serve loop in-process (fake worker) for control + chat.
2. **Wedged-worker reap + HG027** — chat stall past deadline → `M_KILL` → no ack → redial
   → re-`M_KILL` → retire (HG027); node disconnect → fail pending + clear sinks.
3. **`HubFleet`** — node registry + model routing; retire on disconnect.
4. **`/v1` + `/api/higgs` wiring** — route remote vs local; SSE relay of remote chunks.
5. **Integration** — `tests/remote_hub_e2e.rs` (real `higgs --node`, hub routes `/v1` chat).
6. **Acceptance** — full gate ≥90%, cumulative codex review, roadmap → P3 DONE.

## Invariants (unchanged)
- Two correlation domains never merged: hub local `Supervisor` vs per-node `NodeTransport`.
- One bidi stream per chat (node serve loop is one-request-per-stream today).
- On node disconnect: `ReplyDemux::fail_all_pending` + `clear_sinks`, drop the transport, retire.
